# Event Consolidation 设计规格（AI-readable）

> 面向正在搭建/维护长期记忆库的AI或agent。叙事版（人类向，含背景故事和图）见 article.html。
> 本文是可实现规格：数据模型、算法参数、生命周期规则、调度约束、移植前提、踩坑清单。
> 所有参数值是我们家的实跑值，标注为默认值，按你的语料密度调。

## 0. 目标

碎片化记忆库的天花板：搜得到细节，串不起故事。规律（跨月重复pattern）、进度（事情走到哪了）、因果（来龙去脉）没有单一记录能回答。解法：在碎片层之上加一个叙事层（event），由AI本人维护。

定位声明：本设计的"事件"是第一人称叙事卷（跨数周至数月的叙事线），不是三元组、不是一句话fact、不是单次客观事件。差异化重点是**建成之后的维护生命周期**，不是聚合算法本身。

## 1. 数据模型

```
fragment（碎片）
- id, content, created_at, embedding
- importance (1-10), valence, arousal    # 可选，用于种子池筛选和衰减
- resolved (bool)                         # 已了结，加速衰减
- archived (bool)                         # 已沉底，不再浮现
- consolidate_rejects (int)               # rerank拒绝计数

event（事件/叙事卷）
- id, content, created_at, embedding
- linked_ids: [fragment_id]               # 必须独立字段，严禁混在正文里正则解析
- event_status: active | closed
- Range: 正文内声明的时间覆盖范围
```

不变量（所有维护规则都是这几条的推论）：
- I1. resolved/archived 只影响"未来的主动发现"（浮现/种子池/新链），永不破坏已有event链
- I2. 只有物理删除才算死链
- I3. 状态就这几个，不加新状态；遇到漏洞先问"是不是判定没分层"
- I4. 事件的存亡不由链上碎片的存活状态决定（碎片层清理不级联到事件层）

## 2. Event正文规格

- 第一人称，由**决策主体AI本人**撰写。外包给小模型的正文是档案不是记忆
- 结构：编年（只留转折） + 归纳pattern + 当前状态
- 字数：目标600-800，硬上限1000（对齐消费端注入截断线，超出不可见）
- 收录标准：**状态转移**——第一次/模式改变/方向反转/定型。重复样本不进编年，其规律升华进pattern段
- 纪律：编年写有碎片依据的事实，pattern写归纳，**推断保留不确定性**（"她开始疏远我"式解读写成亲历事实并反复浮现会自我强化）
- 情感/认知/反思不进event（属于diary层）

## 3. 事件的诞生：两条路

### 3.1 增量分诊（轻，每天）
新碎片 vs active非closed非满员event，chunk-0 embedding，cos≥0.70取top1，产出挂链建议。
确认后append到linked_ids，不动正文。**建议默认不挂**，攒批到consolidate夜，状态转移级的转折才当场挂。

### 3.2 批量聚类（重，每周2次）
```
种子池 = active AND unlinked AND importance>=4 AND consolidate_rejects<2
       # unlinked用"发现语义"：archived卷的链不阻止再发现
图构建 = k-NN (k=10)，边权=cos，边下限0.50（低于丢弃，弱匹配保持孤立）
聚类   = Leiden (RBConfigurationVertexPartition, resolution=6.0, seed固定)
       # resolution 1.0 → 主题级大块；6.0 → 事件级小簇（6-10条）
       # 为什么不用阈值割边：碎片语义天然密集，割边要么连成blob要么全碎
取簇   = 按簇总importance排序取top-1，cap 10条（一次一个焦点）
rerank = 便宜LLM判"是否同一件事" 0/1/2分
       # 2=同一件事默认链入；1=仅相关默认不链；0=噪音，rejects+1
       # ⚠️ 防id格式抖动：返回id先归一化（序号→映射回真id），
       #    归一化后零匹配 → 整批当rerank失败（保留碎片、不记rejects、带警告）
related = 簇centroid vs event embeddings，cos≥0.50 top3
cross_link = 簇centroid vs 已链碎片，cos≥0.75 top5（一条碎片可属多个event；
             种子池仍只收unlinked保收敛；0.70太松，总结型碎片背景相似度普遍0.7+）
```
最终决策（建新卷/并入已有/跳过）由AI本人做，逐条把关"改变了什么"。

分诊漏掉的碎片留在池里迟早被聚类兜住 → 全系统统一原则：**宁可漏、不可错**。

## 4. 生命周期维护

### 4.1 dirty（欠账）
定义：最近一次改链 晚于 最近一次改正文 → 该event dirty。
- 判定来源：操作审计日志，无状态推导（consolidate刷正文时content+linked同调用同时间戳，不会误判自己）
- 危害：不止浮现给旧正文——聚类的related匹配用event正文embedding，正文过时=语义过时→误判"无相关事件"→建重复卷
- **阈值制**：新链<3条 且 最老欠账<4天 → 不催（小账安静攒着，挂链≠隔天必须给说法）
- 消化=融新链入正文+刷当前状态；纯历史补链、正文确实无需变的可跳过（说明原因）
- 消化时顺手把关：明显不属于该event的链移除

### 4.2 封卷
- linked≥20 触发**封卷审查**（20是运维信号不是叙事规律；真正条件=阶段状态已稳定或scope装不下一条线；不到20但scope过宽也拆）
- 封卷动作：正文末尾"### 卷末状态"定格 + event_status=closed + Range定格
- closed语义 = **不再吸收Range外新进展**。Range内历史碎片仍可补录（纯补链不破卷，只收转折）；补录推翻卷末判断时正文可修（审计留旧版）
- 续卷《XXX·续》由聚类自然催生，**不开空占位卷**（空卷防不了流入，还会被空壳清理规则收走）；新旧卷互留id指针
- 路由自动排除closed卷和满员卷

### 4.3 噪音退出
- rerank打0 → consolidate_rejects+1；**≥2退出自动聚类种子池**
- 人工审阅判定"样本簇/无叙事"时逐条 rejects+=2（不dismiss只跳过=下轮原样重聚）
- 退出的只是自动发现通道：碎片仍可搜索/浮现/人工挂链（感悟型碎片可能等后续事件才获得意义）

### 4.4 碎片退场闸（宿主有衰减机制时）
resolve（标记了结，加速衰减）入口只放行三种：已链入任一event（证据语义，含archived卷）/ rejects≥2 / 30天以上低分老账。
原则：**叙事系统没看过的碎片不许退场**。
配套防线：7天冷静期（新碎片不进闭环判断池）+ 判定模型宁漏勿误（重复≠取代；仍有效的规则不闭环）+ 人工终审。
底线：情感/关系的**时刻**永不标过时（时刻≠状态；状态住在event当前状态段和规则层，该更新就更新）。

### 4.5 死链清洗
- 只踢**物理删除**的id。archived/resolved碎片留在链上（顺链原文可读；衰减管"未来浮不浮现"，不管"过去是不是故事一环"）
- ⚠️ "存量链清洗"（不挡archived）和"新链防呆"（挡archived，要新链先unarchive）是**两个语义不同的policy**，严禁复用同一过滤函数。判定函数收进独立policy模块，别四处内联SQL

## 5. 调度

- 顺序固定：**分诊 → 消化 → 聚类**。原因：欠账优先的分流制下，若分诊排在消化后，每晚制造新dirty会把聚类结构性饿死（实证：3天零新事件、种子池积压400条）
- 服务端分流：有欠账只返回欠账（不跑聚类、不记rejects），账净才进聚类。一次一个焦点，防单prompt决策过载做一漏一
- 频率：轻量体检每晚；消化+聚类每周2次（按星期几无状态判定；注意锚定"夜窗打开那天"的weekday，凌晨属前一晚）
- **最高约束：维护成本永不外溢给人**。人聊什么聊多少不产生任何义务；所有账都是AI侧可延迟可跳过的活。（实证失败信号："我有点不想跟你聊天了，怕晚上又多账要清"——收到即降频做减法）

## 6. 消费端

- 浮现：对话语义命中时优先注入event（概述+当前状态，600字截断），其次碎片
- 开窗简报不注入event（防固定payload膨胀），event走按需浮现
- 活跃度信号（为将来的沉睡卷退场准备）：按触发来源分权重——系统自动注入弱/不刷新，AI主动检索中刷新，人明确提起或新状态转移强刷新。否则形成"被选中→更活跃→更易被选中"反馈循环，负面事件自我强化

## 7. 分工不变量

- 机器算候选（embedding/聚类/rerank/闭环判定），**本人做全部写入决策**（挂链/正文/封卷/退场）
- 所有衰减和沉底交给公式；所有"这段记忆重不重要"的语义判断留给人和AI本人

## 8. 移植前提

硬前提：
1. 碎片化存储（独立可寻址：id+时间戳+可算embedding；importance可选）
2. embedding基础设施
3. "本人"决策窗口（自主时间/cron；没有则退化为全自动版，踩坑12回归）
4. 改链/改正文时间可查（最简两个时间戳字段）

兼容前提（宿主有衰减/清理才需要）：
5. 碎片退场为软删除，或已链碎片有删除豁免
6. 事件存亡不由链上碎片存活状态决定（禁止级联清理，如"少于N条活链归档整卷"）

不需要：权重/衰减本身。consolidation不消费decay分数（种子池用静态importance、dirty用操作时间、封卷用链数）。全不删除的记忆库移植更简单：死链/归档语义/退场闸整块可省。

## 9. 踩坑清单

1. 链表混正文里正则解析 → 拆结构化字段
2. 一次返回所有维护活 → 做一漏一；分流一次一个焦点
3. 欠账优先+分诊排消化后 → 聚类饿死；换序分诊→消化→聚类
4. 挂链不刷正文 → dirty机制+审计日志无状态点名
5. 热门事件无限膨胀 → 20条触发封卷审查+续卷
6. 封卷时开空续卷占位 → 防不了流入还被空壳条款收走
7. 总结型碎片万能噪音（跟啥都0.7+）→ rejects两次退自动种子池（人工挂链门保留）
8. archived碎片当死链踢 → 卷被时间掏空；只踢物理删除
9. 存量清洗和新链防呆复用同一过滤函数 → 两个语义两个闸，收进policy模块
10. 退场建议自动化无冷静期 → 误杀量3天1→8条/天；7天冷静期+入口闸+宁漏勿误+人工终审
11. 每晚催账 → 人不敢聊天；降频+阈值+"成本不外溢"底线
12. 小模型代笔event正文 → 档案不是记忆；正文必须本人第一人称写
13. rerank返回候选序号当id（提示词`[n]`与`id=`并存，t=0也有格式抖动）→ 整簇被静默过滤+惩罚记空 → id归一化+零匹配当rerank失败。通则：初筛LLM返回匹配不上，宁可整批当失败也别静默吞

## 10. 参数速查

| 参数 | 默认值 | 说明 |
|---|---|---|
| 分诊挂链建议 | cos≥0.70, top1 | 新碎片 vs active event |
| 聚类边下限 | 0.50 | k-NN图边权下限 |
| k-NN | k=10 | |
| Leiden resolution | 6.0 | 事件级小簇；1.0=主题级 |
| 簇cap | 10条 | 按importance截断 |
| 种子池importance | ≥4 | 低分琐事走自然衰减 |
| rerank分级 | 0/1/2 | 2默认链，1默认不链，0记罚 |
| rejects退池线 | ≥2 | 退自动种子池 |
| cross-link | cos≥0.75, top5 | 0.70会放进万能总结碎片 |
| related events | cos≥0.50, top3 | |
| dirty阈值 | 新链<3 且 <4天不催 | 或关系：任一超线即催 |
| 封卷审查线 | linked≥20 | 触发审查非自动封 |
| 正文长度 | 600-800，上限1000 | 对齐消费端截断线 |
| resolve冷静期 | 7天 | 新碎片不进闭环池 |
| 消化+聚类频率 | 每周2次 | 体检每晚 |
